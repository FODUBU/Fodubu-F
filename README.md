Welcome to the official documentation repository for the FODUBU Ecosystem token project. This repository provides public documentation, network metadata, token allocation records, and technical resources supporting the development and verification of the FODUBU ecosystem.

FODUBU stands for Force de Développement et Ubuntu au Burundi. Its mission is to support community-driven economic development through interconnected commerce, environmental sustainability, agriculture, and digital services.

This repository promotes transparency, responsible development, and a clear separation between testnet experimentation and production deployments.

🚀 5. Launchpad, Staking, and Vesting

FODUBU intends to develop a transparent framework for token distribution, ecosystem participation, and applicable token-locking arrangements.

The availability of each feature depends on the supported platform, the actual implementation, and any applicable network requirements.

Launchpad

FODUBU intends to use an appropriate Launchpad mechanism to support the transparent introduction and distribution of its ecosystem token, subject to the capabilities, eligibility requirements, and rules of the selected platform.

The project will document the applicable launch process, allocation terms, distribution conditions, and relevant network identifiers as these are established and verified.

Any Launchpad-related distribution must clearly distinguish between testnet FTEST and mainnet F.

A project plan or public metadata file does not itself constitute an active Launchpad offering or confirm that a token has been listed or approved.

Staking

Staking is an intended ecosystem feature, subject to implementation through a supported and appropriately secured mechanism.

Before a staking program becomes operational, its documentation should specify:

- Eligibility requirements.
- Minimum or maximum staking amounts, if applicable.
- Lock-up periods and withdrawal conditions.
- Reward calculation and distribution rules.
- Applicable fees, risks, and penalties, if any.
- The mechanism used to account for and distribute rewards.

No staking availability, reward rate, or return should be considered confirmed until the corresponding implementation is operational and verified.

Vesting

FODUBU intends to use an appropriate Launchpad or another suitable mechanism to manage applicable mainnet token vesting.

Vesting documentation should identify:

- The allocation category or beneficiary.
- The initial unlock amount, if any.
- Any cliff period.
- The vesting duration and release frequency.
- The mechanism enforcing the schedule.
- The conditions for changes, cancellations, or early releases, if supported.

Actual vesting schedules will be published when finalized and verified.

FTEST is for technical testing only. Holding or receiving FTEST does not create a claim to mainnet F tokens, Launchpad allocations, staking rewards, or vested tokens.

FODUBU's proposed project reference ratio is:

1 F = 0.04 Pi

Equivalently:

1 Pi = 25 F

This ratio represents the intended FODUBU project reference relationship. It must not be interpreted as proof of an established exchange market, guaranteed redemption, or guaranteed liquidity.

USD reference calculation

For project calculations, using the stated reference assumption:

1 Pi = US$314,159

The corresponding calculated reference is:

[

]

Calculated reference: US$12,566.36 per F

This is a mathematical conversion based on the specified Pi reference rate. It is not a verified market price or a promise that F can be sold, exchanged, or redeemed at that amount.

Actual prices, if trading becomes available, depend on the applicable market, liquidity, trading arrangements, and platform rules.

The Pi reference rate must be explicitly identified as a project assumption unless independently established by a reliable, applicable source or an enforceable mechanism.

Reference value and token accounting

- The proposed F/Pi ratio applies to the project's stated mainnet reference policy.
- The USD calculation is derived from the specified Pi reference rate.
- A reference ratio does not automatically set an on-chain exchange rate.
- A displayed reference value does not guarantee purchasing power or redemption.
- The reference value does not apply to FTEST.
- Testnet FTEST must not be used as a substitute for mainnet F.

Any application displaying this reference must distinguish a project-defined reference value from a verified market quote or an actual executable transaction price.

🔐 8. Repository Security and Access Control

FODUBU uses public documentation to promote transparency while restricting repository modifications to authorized collaborators.

Recommended controls include:

- Repository visibility: Public for documentation intended for public access.
- Read access: Available to the public.
- Write access: Restricted to authorized collaborators.
- Branch protection: Use protected branches and pull-request reviews where available.
- Change review: Review metadata, allocation changes, and network configuration updates before merging.
- Secret protection: Never commit private keys, seed phrases, signing keys, passwords, or API secrets.

Public documentation does not grant visitors permission to modify the repository or authorize them to issue tokens.

Repository access permissions are separate from token issuer authority, validator permissions, and smart contract administration.

- Maintain separate testnet and mainnet configurations.
- Validate network and token or contract identifiers.
